# rquickshare - notes for Claude Code

Shared project rules for anyone working on this repo with Claude Code. Put
personal preferences in `CLAUDE.local.md`, which is not committed.

rquickshare is Google Quick Share for Windows 11 and Linux (macOS builds, but
nobody is known to use it). It's a Rust core plus a Tauri v2 / Vue app,
developed at **asulwer/rquickshare**. It started as a fork of
Martichou/rquickshare by Martin André. Credit him in docs, but never point
anything at that repo: links, update checks, issues or PR targets.

## Layout

- Cargo workspace, with all build output in the root `target/`:
  - `core_lib`: crate `rqs_lib`, the protocol, transports and crypto.
  - `app/main/src-tauri`: crate `rquickshare`, the Tauri shell.
- `app/main`: the Vue 3 / TypeScript / Pinia / Tailwind frontend, built with
  pnpm.
- `core_lib/bindings/*.ts`: generated by ts-rs from the Rust types. The app
  imports them as `@martichou/core_lib/bindings/<Type>`. That package name is
  internal only.
- The BLE and Wi-Fi Direct transports sit behind the `experimental` cargo
  feature, which is on by default. The Windows code uses the `windows` crate
  (WinRT and Win32). The Linux code uses `bluer` (BlueZ).
- Docs: `README.md`, `BUILD.md`, `KNOWN_ISSUES.md`, `TODO.md` and `docs/*.md`.

## Rules

- **No warnings, and never silence one.** Fix the cause. That rules out:
  - `#[allow(...)]`, `let _ = value;` used to discard a value, and
    `_`-prefixed names that only dodge an unused warning;
  - `eslint-disable`, `@ts-ignore` and `@ts-nocheck`.

  When something only applies on one platform, scope it with `#[cfg]` instead.
  RAII guards held for their `Drop` (`let _pause = ...`) are fine.
- **Event-driven, not timer-driven.** Don't add fixed sleeps, polling loops,
  retry backoffs or arbitrary timeouts in place of waiting for the thing that
  actually changes. Use a watch or channel, a WinRT event, a BlueZ or btleplug
  event stream, or `CancellationToken`. If something must have a bound, say in a
  comment which event it stands in for.
- **Stable Rust only, never nightly.** No nightly features and no
  `rust-toolchain` pins to nightly.
- **Treat everything a peer sends as hostile.** Data from a nearby phone or LAN
  host arrives before anyone is authenticated, because UKEY2 is anonymous. Over
  TCP, BLE GATT and Wi-Fi Direct:
  - Bound every buffer by the size the peer declared and by the frame limit.
  - Never `unwrap()` or index on peer data.
  - Sanitize file names (`utils::sanitize_file_name`) and create files with
    `create_new` (`utils::create_unique_file`).
  - Don't act on a transfer's payload before the user has accepted it.
- **American English** in code, comments, docs and PR text.
- **Comments say why**, in the same density and voice as the surrounding code.
- **Versions are not edited by hand.** `Cargo.toml` stays at `<major>.0.0`, and
  the Release workflow stamps `<major>.<YY>.<DDD>+<build>` at release time. Only
  `pnpm bump major` (`scripts/bump.mjs`) changes the major number.
- **Don't bring back** release-please, AppImage bundles or `-latest` Linux
  runners. CI is pinned to `ubuntu-24.04`.

## Before you push

Run these. CI (`.github/workflows/check.yml`) runs the same checks, and a PR
must pass them.

```sh
cargo fmt --all --check
cargo clippy --workspace --all-features --all-targets -- -D warnings
cargo test --workspace --all-features
cd app/main && pnpm lint && pnpm ts-check && pnpm vitest run
```

- **Platform code you can't compile locally:** clippy only checks your own OS's
  `#[cfg]` code. CI runs clippy on both Linux and Windows, so watch both jobs.
- **Line-ending churn after tests:** `cargo test` regenerates
  `core_lib/bindings/*.ts`. If the only difference is line endings, discard it
  with `git checkout -- core_lib/bindings` rather than committing it.
- **Rust formatting:** `.claude/settings.json` runs rustfmt on every `.rs` file
  Claude edits.

## Commits and PRs

- **Conventional commit subjects**, matching the history: `fix(ble): ...`,
  `feat: ...`, `chore(deps): ...`, `ci: ...`, `docs: ...`, `test: ...`. Keep
  subjects short and put the reasoning in the body.
- **Target asulwer/rquickshare `master`, never the upstream fork.** GitHub
  still lists this repo as a fork of Martichou/rquickshare, so check the base
  repository on the PR page.
- **PR titles become the release notes** (`gh release create --generate-notes`),
  so write them for users.
